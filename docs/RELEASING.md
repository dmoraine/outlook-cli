# Releasing

Releases are cut by the owner only. CI (`.github/workflows/ci.yml`) builds the Windows executables once, in the
`windows` job; the `package` job hashes them and the `release` job publishes them. Nothing is rebuilt between the
dry run, the checks and the release.

## Assets

Each GitHub Release has exactly three assets:

- `outlook-cli.exe` — default features, no SQLite or embedding stack.
- `outlook-index.exe` — built with `--features index`.
- `SHA256SUMS` — `sha256sum` output for both executables.

Both executables also get a GitHub artifact attestation (SLSA build provenance, `actions/attest-build-provenance`).
Release notes are generated by GitHub from the merged PRs and commits.

## Cutting a release

1. Bump `version` in `Cargo.toml` (both binaries report it with `--version`), then refresh `Cargo.lock`
   (`cargo check`). Commit on `main` (`Release vX.Y.Z`).
2. Checks: CI green on that commit — `linux` (fmt, clippy and tests with and without `--features index`, no SQLite or
   embedding crates in `outlook-cli`) and `windows` (tests, builds, `--version` of both exes).
3. Dry run (also usable on any branch before merging pipeline changes): Actions → CI → *Run workflow*, or
   `gh workflow run ci.yml --ref main`. It runs every job except `release` and uploads the
   `release-assets` workflow artifact (both exes + `SHA256SUMS`). No release, no tag, no attestation.
4. Tag and push; the tag must match the `Cargo.toml` version:

   ```bash
   git tag -a vX.Y.Z -m vX.Y.Z
   git push origin vX.Y.Z
   ```

   The tag push runs the checks, then `release` attests both exes and creates the release with the three assets.
5. Check the release page: three assets, notes, and the verification below passes.

Do not create a release by hand (`gh release create`): it would have no attestations.

## Verifying a download (users and agents)

Download the assets into one directory, then:

```bash
sha256sum -c SHA256SUMS                                  # both lines must say OK
gh attestation verify outlook-cli.exe   --repo dmoraine/outlook-cli
gh attestation verify outlook-index.exe --repo dmoraine/outlook-cli
```

PowerShell, without `sha256sum`: compare `(Get-FileHash outlook-cli.exe -Algorithm SHA256).Hash` (case-insensitive)
with its line in `SHA256SUMS`, same for `outlook-index.exe`.

`scripts/install.ps1 -Version vX.Y.Z` (native PowerShell) and `scripts/install.sh --release vX.Y.Z` (WSL) run these
checks and install nothing if one fails.

A hash mismatch or a failed attestation means: do not run the file; build from source instead
(`docs/WINDOWS_TESTING.md`). If `gh` is not available, the SHA-256 check alone is the minimum.
